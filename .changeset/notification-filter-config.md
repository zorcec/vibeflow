`vibeflow notifications` can now be subscribed: a `.vibeflow/notifications-filter.json` config file plus repeatable `--filter-<dim>` flags (taskId, type, actor, status, taskType — repeats are OR within the dimension) narrow what the follower reads SERVER-SIDE, so filtered events are dropped by the board and reported through `filteredCount`, never filtered client-side after the fact. The loader is strict and loud: a missing file is the silent default, an unreadable or invalid-JSON file warns once and follows unfiltered (never a silent empty feed, never a crash), an invalid value drops that dimension while the rest of the file still applies, and an unknown key is warned and ignored. Flags merge over the file and win per dimension; `--no-filter` (alias `--filter-reset`) bypasses the file entirely. Values serialise as repeated query params (`actor=a&actor=b`) and blank elements are never emitted. On `--follow`, a preview line (`filters: type=task.comment · 3 events in window, 1 delivered, 2 filtered`) prints at startup and reprints whenever the numbers change, straight from the server's `filteredCount`; a board that answers 400 to the filter gets one warning and the follower continues unfiltered instead of dying. The direct local file read resolves `taskType` from the project's own task list, matching the served route's behaviour.
